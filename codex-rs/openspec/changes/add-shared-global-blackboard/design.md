## Context

当前 Swarm 协作上下文主要依赖会话内历史与 summary 注入，缺少一个可被多个智能体共享、可跨轮次读写的统一关键信息载体。用户要求新增全局共享黑板，并满足以下约束：

- 黑板存放在工作目录 `.blackboard/` 下，不存在时自动创建。
- 每个会话维护一个独立黑板文件，会话启动时自动创建。
- 黑板读写必须由智能体通过 shell 工具执行，不引入额外专用写入工具。
- 黑板写入格式固定为 `[智能体名字]：消息内容`。
- 每轮都要注入“最后的 user-assistant 对话对”，其内容应包含其他模型的历史 summary 以及共享黑板内容。
- 需要并发锁防止多智能体同时读写导致冲突。
- Swarm 系统提示词要新增黑板规则，并自动注入当前会话黑板文件路径与智能体名字信息。

该需求跨越会话初始化、提示词组装、shell 执行约束与并发控制，是一个跨模块改动。

## Goals / Non-Goals

**Goals:**

- 在每个会话启动时确保 `.blackboard/` 与会话黑板文件已就绪。
- 将黑板路径和使用规则自动注入 Swarm system prompt。
- 统一黑板写入格式为 `[agent_name]：message` 并要求模型遵循。
- 通过锁机制保证并发读写一致性与可预期行为。
- 在模型上下文注入中稳定携带最近 user-assistant 对话对（含 summary 与黑板内容）。
- 提供可复现测试，验证格式、会话隔离、锁行为、注入完整性，并能结合 debug 目录排障。

**Non-Goals:**

- 不引入数据库或远程共享存储；黑板仍是本地文件。
- 不改变现有业务工具的语义（仅增加黑板使用规则与上下文注入）。
- 不在本次变更中实现复杂权限系统（默认同会话智能体可读写）。
- 不替代现有 summary 机制；黑板是补充通道而非替换。

## Decisions

### 1. 会话级黑板文件生命周期

决策：

- 约定黑板根目录为 `<workspace>/.blackboard/`。
- 约定会话黑板文件路径为 `<workspace>/.blackboard/<session_id>.md`。
- 会话初始化时执行“目录存在检查 + 文件存在检查”，不存在则创建空文件。
- 运行时将该路径挂到会话上下文，供提示词构建与后续注入使用。

理由：

- 会话文件天然隔离，避免不同会话互相污染。
- 文件命名依赖现有 `session_id`，无需引入新的标识分配器。

备选方案：

- 单一全局文件：被拒绝，无法满足“每个会话一个文件”的隔离要求。
- 以智能体划分文件：被拒绝，需求明确是“每会话共享黑板”。

### 2. 黑板读写契约与格式强约束

决策：

- 只允许智能体经 shell 工具修改黑板（如 `printf >>`、`sed -i` 等）。
- 写入格式固定为 `[agent_name]：message`，其中 `agent_name` 来自系统提示词注入的当前智能体名。
- 对多行消息进行规范化：写入前压平为单行或显式换行转义，避免破坏解析。

理由：

- 该契约与用户要求一致，且无需额外维护专用工具 API。
- 固定格式便于后续调试检索、自动校验与冲突审计。

备选方案：

- 新增 `blackboard_write` 工具：被拒绝，和“依赖 shell 工具执行”相冲突。
- JSON 行格式：被拒绝，需求指定了人类可读的固定文案格式。

### 3. 并发一致性采用文件锁（advisory lock）

决策：

- 每次黑板读/写前先获取会话级锁文件（例如 `<session_file>.lock`）。
- 使用 `flock` 包裹读写关键区；写操作失败或超时时返回明确错误，并指导重试。
- 对“读取后修改再写回”的场景强制在同一锁持有期内完成，避免读到旧快照。

理由：

- `flock` 在当前 Linux 运行环境可用，集成成本低且行为可预测。
- 能覆盖多智能体并发写入、交叉读写的核心一致性风险。

备选方案：

- 仅依赖追加写：被拒绝，无法保障修改类操作的一致性。
- 内存锁（进程内 mutex）：被拒绝，无法覆盖跨进程 shell 命令并发。

### 4. 注入策略扩展：始终附带“最后 user-assistant 对”

决策：

- 在每轮 prompt 组装末尾附加一个标准化的“最后 user-assistant 对”片段。
- 该片段的 assistant 部分包含：其他模型历史 summary 摘要 + 当前共享黑板内容快照（必要时截断）。
- 黑板快照读取也走锁，保证注入内容与磁盘一致。

理由：

- 与用户提出的注入要求一致，并最大化保留协作上下文。
- 将黑板与 summary 放在同一注入块，便于模型联合理解。

备选方案：

- 仅注入黑板不注入对话对：被拒绝，不满足明确要求。
- 只在首轮注入：被拒绝，需求是“每次都应注入”。

### 5. Swarm 系统提示词增量规则

决策：

- 在 swarm system prompt 中新增黑板规范段，包含：
- 当前智能体名称（用于写入前缀）。
- 当前会话黑板文件绝对路径。
- 黑板读写必须使用 shell，并遵循锁机制。
- 写入格式必须为 `[智能体名字]：消息内容`。
- 会话启动时，自动把黑板路径动态填充到提示词模板。

理由：

- 用户要求“每个智能体知道自己的名字”与“路径自动填充”。
- 通过 system prompt 强约束模型行为，比仅靠文档约定更稳。

备选方案：

- 仅在开发文档中说明：被拒绝，无法保证模型运行时一定遵守。

## Risks / Trade-offs

- [Risk] 锁等待可能增加工具调用延迟。 -> Mitigation: 设置合理超时与有限重试，并在日志中标注锁争用。
- [Risk] 模型可能偶发写出不符合格式的行。 -> Mitigation: 提示词显式约束 + 测试校验 + 运行时诊断告警。
- [Risk] 黑板内容过长导致上下文膨胀。 -> Mitigation: 注入时按长度上限截断，保留最近关键片段。
- [Risk] 会话 ID 到文件名映射错误导致串会话。 -> Mitigation: 增加会话隔离测试并在 debug 日志中输出映射关系。
- [Risk] 不同 shell 写法差异影响兼容性。 -> Mitigation: 在提示词中提供推荐写法（`flock` + `printf`）并增加集成测试。

## Migration Plan

1. 在会话初始化流程中落地 `.blackboard/` 与 `<session_id>.md` 自动创建逻辑。
2. 扩展 swarm system prompt 模板，注入智能体名、黑板路径和读写规则。
3. 在上下文注入流程中追加“最后 user-assistant 对”构造逻辑，并接入黑板快照读取。
4. 在 shell 黑板操作路径引入 `flock` 锁策略与错误处理。
5. 新增测试：格式约束、会话隔离、并发锁、注入内容完整性。
6. 使用 `/media/wmj/BC0739C74EA78EEA/debug` 运行记录验证黑板与注入输出是否符合预期。

回滚策略：

- 通过配置开关禁用黑板注入与提示词扩展，保留现有 summary 注入链路。
- 不删除 `.blackboard/` 已有文件，仅停止读写与注入，避免数据破坏。

## Open Questions

- 会话黑板文件名是否需要加入时间戳以便人工检索，或仅用 `session_id` 即可？
- 黑板快照注入的长度上限应设为固定字符数还是按 token 预算动态裁剪？
- 对历史黑板文件是否需要引入清理策略（例如按会话结束后保留 N 天）？
